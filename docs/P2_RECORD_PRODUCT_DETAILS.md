# P2 · 喂食、用药与记录用品详情

状态为需求待评审。一人负责接口、迁移、记录页、只读查询兼容、本机实测与提审。此需求收窄此前延期的喂食与药品有效期提案，独立于 #93 的洗澡记录草稿。

## 首版需求

- 日常记录新增喂食（`feeding`）和用药（`medication`），沿用实际发生日期、宠物、名称和备注。支持新增、查看、修改、删除与类型筛选。
- 喂食记录食品，驱虫记录驱虫用品，用药记录药品，疫苗记录疫苗。每条对应一种用品。复用现有 `name` 作为名称，增加可选的包装有效期 `product_expires_on` 和商家/来源 `product_vendor`（如购买店铺、医院）。厂商、批号、用量等首版可写在备注。
- 有效期使用 `YYYY-MM-DD`，允许未来日期，也允许记录包装有效期早于实际发生日期的历史事实。日期不明确时留空，可在备注保留包装原文。有效期表示包装标注日期，独立于记录发生日期、开封后期限和下次护理时间。
- 用品信息随记录保存。首版范围为记录与查询，用品库存、扫码识别、自动提醒和剂量或护理建议另行评审。

## 现有接口与兼容

- 复用 `/api/v1/records` 的 CRUD、筛选、错误格式及 Service。扩展 Pydantic、SQLAlchemy、数据库类型约束、Alembic 迁移和前端类型，现有 `name`、`notes`、`weight_kg` 及提醒引用语义保留。
- 旧数据新增字段为空，无需回填。POST 新字段可省略。PATCH 省略保留原值、显式 null 清空。对更新后的完整记录联合校验，洗澡和体重记录只接受空用品详情。切换到不支持详情的类型时，表单提示并由用户确认清空，API 拒绝残留不适用的详情。仅体重类型可填写体重。
- 记录表单按类型展示用品字段，列表和详情有值才展示。现有 Agent 查询继续只读，核对类型白名单、标签和工具输出，能按新类型过滤并如实复述有值字段。同步 API 文档及任务状态。

## 先本机真实验证，再评审

1. 在带旧记录及提醒关联的测试 SQLite 库运行迁移，通过真实浏览器和 FastAPI 验证旧记录可读，关联、筛选和体重趋势仍正常。
2. 分别新增喂食和用药记录，为驱虫与疫苗补录用品信息。验证刷新后持久化、日期和商家显示、类型筛选、修改清空及删除。覆盖非法日期、洗澡/体重填用品字段、切换类型保留不适用字段的请求。
3. 使用真实 Qwen 在本机查询新增类型和用品详情，核对结果与数据库一致，缺失字段如实说明。Mock 与自动化测试作补充。缺少真实模型凭证时记录阻塞，实测通过再提审。
4. PR 附脱敏实测输入和结果。只复核影响验收、兼容性或数据完整性的阻塞项，非阻塞意见记录即可。
