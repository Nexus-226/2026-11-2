## 状态怎么维护

- 使用 `未开始`、`进行中`、`待审核`、`已完成`。负责人领取后更新状态，提 PR 后填链接并标为待审核。
- 任务表保存在 Git 分支中：在功能 PR 里修改状态，在该 PR 合并前不会出现在 `main`。未合并期间的实时进度以对应 Issue 和 PR 为准，不把分支里的状态当成主分支已更新。
- 有代码的任务在对应 PR 合并、必要验证通过后标为已完成；共同确认类任务由 A、B、C 都确认后完成。一个任务可以拆成多个小 PR。
- 合并后由任务负责人补交小型文档 PR，更新对应任务行、PR 链接、验证依据及相关进展段落，并核对 README、REPOSITORY_STATUS 中的状态说明。只完成部分子项时保留未完成依赖。结束回复必须说明本表是否已更新，未更新则列出原因与剩余动作。
- 下表为根据当前 `main` 整理的初始快照；团队成员如已在其他分支工作，请自行更新状态，避免重复开发。
- 接口变更先通知 A、B、C，更新契约草案；至少一名其他成员评审，涉及接口的任务由使用方确认。
- 任务编号用于跟踪工作，**不等于 GitHub 的 PR 编号**。PR 先合接口、再合功能；每个 PR 保持独立、可启动和可验证，按 PR 指南小步拆分并尽量每日合并。

### 历史来源、Provider 与窗口

- 数据库是跨用户请求会话历史的唯一来源，前端不上传整段历史，Provider 不充当持久会话存储；Provider 按请求创建，不使用跨会话共享的全局消息状态。
- “每次重建”指每次用户请求开始时初始化，不是每一次模型调用都重置。Provider 可以保存同次用户请求内部的临时消息，保留本轮 assistant 工具调用、对应 `tool_call_id` 和工具结果，直到最终回答。
- A/B 先确认内部历史结构；回放只包含历史用户消息及助手最终回复的 `role`、`content`，不拼回数据库中的 `tool_calls` 摘要，也不重放历史工具结果。当前轮次的真实工具交互仍正常发送，不能把两者混淆。
- 首版最多携带最近 10 个完整轮次（20 条 user/assistant 消息），并加明确字符预算；历史较短且预算允许时全部带入。字符上限由 A 在实施 PR 中明确，给系统提示、本次问题、工具定义、当前工具结果及输出预留空间；字符数是保守限制，不视为精确 token 计数。
- 超限时从最早完整轮次移除，不截半条消息，不保留孤立 assistant 或半轮 user。窗口仅影响模型输入，不删除数据库历史；P0 不引入摘要、向量库或历史搜索。

### 消息顺序、迁移与事务

- B 为每条消息增加会话内递增 `sequence`，建立 `(session_id, sequence)` 唯一约束及非空要求；同轮用户消息在前、助手回复在后，占用连续序号。读取不只按 `created_at` 排序，UUID 不作为实际先后顺序依据。
- Alembic 迁移先新增字段、回填旧数据，再收紧非空/唯一约束；已有会话逐会话编号，不留下 NULL 序号。需核实旧写入方式与实际 SQLite 数据能否提供可靠插入顺序，再采用时间及经验证的 rowid 辅助回填，不能假设 rowid 或相同时间戳能自动还原对话。
- 对顺序确实无法确定或已有半轮的旧数据，实施 PR 必须明确处理策略并测试；保留原始记录，将不可靠部分排除出模型回放，不编造确定的历史顺序。
- 读历史在前，模型成功返回后才保存本轮；用户消息、助手回复及序号分配在同一保存事务内完成。Provider 抛错或保存失败，不留下本轮单独的用户消息或助手消息。
- 同一事务和唯一约束不等于已解决并发，不能仅依赖 `max(sequence)+1`。C 禁止重复发送；B 对同会话并发明确采用串行处理或冲突拒绝，并保证整轮回滚。若两个请求基于同一历史快照生成，不能只重新分配序号就保存第二个过期回答；应拒绝该轮或基于新历史重新生成，策略在实施 PR 写清。
- 不在等待外部模型期间持有数据库写锁或长写事务；单进程内存锁不能宣称支持多实例并发。P0 不要求引入分布式组件，但必须注明支持范围并测试冲突路径。

### 会话与宠物边界

历史按 `session_id` 获取，当前资料按本次请求的 `pet_id` 经工具查询，系统提示明确当前关联宠物；`pet_id:null` 不从历史自动恢复关联。P0 页面把关联宠物的改变（包括选中与清空）明确作为新会话操作；失败、重试、取消等待本身不触发新会话。

页面规则不能替代后端边界：直接 API 调用仍遵守既有“本次 pet_id 决定关联宠物”的约定，不新增“会话永久绑定宠物”的限制。A/B 利用已存的消息宠物关联信息识别旧上下文，按当前关联处理不相符的历史片段，避免旧宠物资料混入当前事实；内部筛选或标注策略在实施 PR 明确，回放内容仍只用 role/content。为 null 时不得将旧宠物工具资料自动作为当前关联资料。前端切换和直接 API 同会话切换均纳入验收。

对外 `POST /api/v1/chat` 路径、请求/响应字段及既有错误契约保持不变；本节不新增错误码或提前修改 API.md。内部参数和数据库迁移在实施 PR 同步 A/B/C，刷新恢复 UI、历史列表仍留在 P2。
