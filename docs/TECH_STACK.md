## 依赖方向

```text
前端 C → FastAPI 路由 B → Agent A → 白名单工具 A → 服务 B → 数据库/外部适配器 B
                        └──────────────────────→ 服务 B
```

- 宠物、对话和地点等业务数据由前端通过 FastAPI 获取；P1 可使用地图厂商的浏览器 SDK 渲染地图。后端 Web 服务密钥和 LLM 密钥不放到前端或 Git；浏览器地图 Key 使用独立配置和限制，不与后端 Web 服务 Key 混用。
- Agent 不直接执行模型生成的代码、SQL、Shell 或任意 URL；工具经过参数校验并调用服务。LLM Provider 抽象归 A，连接和错误边界与 B 对齐。
- 三方响应先在适配层转换为项目内部结构；前端和 Agent 不依赖高德原始字段。
- P0 先采用单用户本地演示，不实现登录和用户隔离；上线前必须重新设计认证、权限和数据隔离。
- `.env.example` 只是示例，不会被直接加载；LLM 配置已读取环境变量，并在 python-dotenv 可用时加载本地 `.env`。有 LLM_API_KEY 使用 Qwen，否则使用 MockProvider；真实密钥不能提交。

## 会话上下文与宠物事实的数据流

以下是 P0-8 的目标架构，当前历史仅已持久化，尚未接入模型上下文；实施职责、迁移、窗口和验收详见 [任务表 P0-8](TASKS.md)。本节不改变现有对外接口契约。

数据库是跨用户请求会话历史的唯一来源。每次用户请求由后端读取历史并初始化模型上下文，Provider 不承担跨请求记忆；同次请求内部仍保留工具调用及结果。

| 步骤 | 负责人 / 层 | 数据流与边界 |
|---|---|---|
| 1. 发起请求 | C / 前端 | 发送本次问题、session_id 和当前 pet_id；不上传完整历史，按 P0-8 管理新会话及宠物切换 |
| 2. 读取历史 | B / 路由、Service、Repository | 校验会话并从数据库读取本次请求之前的消息，按会话内 sequence 排序；Provider 不直接读取数据库 |
| 3. 初始化上下文 | A / Agent、Provider | 组织系统提示、预算内的完整历史轮次、本次问题；历史只回放 role/content，本次问题只加入一次 |
| 4. 工具交互 | A / 受控工具，B / Service | 按需查询当前宠物数据；Provider 在本次请求内追加真实工具调用及配对结果，继续生成回答，不重复初始化历史 |
| 5. 保存完整一轮 | B / Service、Repository | 模型成功后在同一短事务内分配序号并保存用户消息和助手回复；失败回滚整轮，不在模型等待期间持有写锁 |

### 两类数据的职责

- 聊天历史用于理解“刚才那个”“再详细说说”等对话语义。滑动窗口只裁减本次模型输入，不删除数据库历史；P0 不加入自动摘要或向量检索。
- 宠物档案是已实现的结构化资料；护理记录和提醒是待实现的 P1 业务数据。此类事实通过白名单工具和 Service 按需查询，不仅依赖历史对话，也不自动从聊天文本推断后入库。
- 当前 pet_id 决定关联宠物，历史中的旧资料不能直接当作当前事实；页面切换及直接 API 调用的边界按 P0-8 验收。
- 数据库负责消息顺序与持久化一致性，Agent 负责上下文选择和模型输入，Provider 负责供应商适配及本轮临时交互，前端负责会话操作；并发、旧数据回填与截断细节统一引用 P0-8，不在此重复维护。
